# Технічне завдання: Telegram Mini App Frontend — Функціональне ядро та початковий UI (Фаза 4)

## 1. Загальний контекст
У попередніх фазах створено SQLite WAL базу даних, безпечний REST API (з HMAC initData, RBAC та Race Condition блокуванням) та Telegram-бота з інтерактивними чергами і сповіщеннями.
Мета Фази 4 — створити клієнтський та адмінський фронтенд Telegram Mini App (TMA) на базі **Vite + React + Tailwind CSS**.
Головний пріоритет: **100% реалізація та зв'язка всього функціоналу** (затвердження етапів із цифровим Canvas-підписом, тікети, динамічний прогрес, адмін-перемикач, тактильний відгук Haptics), стабільна адаптивна верстка без візуальних артефактів (нічого не з'їжджає, текст не випадає за межі екрана, кнопки зручні для натискання пальцем на мобільних пристроях).

---

## 2. КРИТИЧНЕ ПРАВИЛО БЕЗПЕКИ ТА ДИСЦИПЛІНИ
- **Zero Secrets Leak:** Жодних токенів, паролів чи секретів у коді чи репозиторії.
- **Rules of Hooks:** Усі React-хуки (`useState`, `useEffect`, `useCallback` тощо) оголошуються суворо на самому початку компонентів. Жодних викликів хуків усередині `if` чи після `return`.
- **Anti-Cache:** Роздача збірки обов'язково через FastAPI з заголовками `no-cache, no-store, must-revalidate`.
- Перед комітом обов'язково запустити `python3 scripts/security_check.py`.

## 4. Детальні функціональні вимоги

### 4.1. Інтеграція Telegram WebApp SDK (`TelegramContext.jsx`)
- Ініціалізація `window.Telegram?.WebApp`:
  - Виклик `tg.ready()` та `tg.expand()`.
  - Синхронізація теми: зчитування `tg.themeParams` (кольори фону, тексту, кнопок) та підтримка автоматичного темного/світлого режиму.
  - Допоміжний метод `haptic(type)`:
    - `tg.HapticFeedback.impactOccurred('light' | 'medium')` при натисканні кнопок.
    - `tg.HapticFeedback.notificationOccurred('success' | 'error')` при успішному підписанні чи помилці.
- Авторизація:
  - Зчитування `tg.initData`.
  - Якщо `initData` порожній (відкриття у браузері або тестування), надсилати `"mock_client"` або `"mock_admin"` залежно від активного режиму в інтерфейсі (підтримується бекендом при `DEBUG=True`).

### 4.2. Перемикач ролей / Демо-режим (Для портфоліо)
- У шапці додати компактний та стильний Switcher: `[ 👤 Клієнт ]` / `[ 👨‍💻 Адмін ]`.
- Дозволяє будь-якому ліду або замовнику поклацати обидві сторони платформи без повторної авторизації.

### 4.3. Клієнтський інтерфейс (Client View)
1. **Картка огляду проекту (Header):**
   - Назва активного проекту, бейдж статусу (`В роботі`).
   - Загальний бюджет (`$2,500 USD`) та сума затверджених етапів.
   - **Інтерактивний прогрес-бар:** відсоток виконання (наприклад, 33.3%, 66.7%, 100%) з плавною анімацією заповнення.
   - Кнопки швидких посилань:
     - `[ 🎨 Figma ]` (відкриває через `tg.openLink`).
     - `[ 🌐 Тестовий стенд ]` (відкриває через `tg.openLink`).
2. **Таймлайн етапів робіт (Milestones Timeline):**
   - Картки етапів у порядку `order_index`:
     - Номер та назва етапу.
     - Опис робіт та вартість етапу.
     - Бейдж статусу:
       - `APPROVED` (зелений: *"Затверджено та підписано"*).
       - `WAITING_APPROVAL` (жовтий/бурштиновий пульсуючий: *"Очікує вашого затвердження"*).
       - `IN_PROGRESS` (синій: *"В роботі у розробника"*).
       - `LOCKED` (сірий: *"Черга робіт"*).
   - Якщо етап у статусі `WAITING_APPROVAL` — під карткою активна велика кнопка:
     `[ ✍️ Затвердити та підписати етап ]`.
3. **Модальне вікно цифрового підпису (Canvas Signature):**
   - Повноекранне або BottomSheet вікно з полотном `<canvas>`.
   - Підтримка сенсорного малювання (події `touchstart`, `touchmove`, `touchend`) та миші.
   - Кнопка `[ 🔄 Очистити ]` для повторного розпису.
   - Кнопка `[ ✍️ Підтвердити підпис ]`:
     - Перевіряє, що підпис не порожній.
     - Кодує у Base64 (`canvas.toDataURL("image/png")`).
     - Викликає `POST /api/client/milestones/{id}/approve`.
     - Запускає успішний тактильний відгук (`notificationOccurred('success')`).
     - Оновлює стан проекту: поточний етап стає `APPROVED`, наступний етап розблоковується в `IN_PROGRESS`, прогрес-бар перераховується.
     - У разі помилки або повторного кліку (`409 Conflict`) показує зрозумілий Toast.
4. **Блок тікетів та зворотного зв'язку (Tickets):**
   - Список зафіксованих правок клієнта з бейджами типів (`🐛 Баг`, `✏️ Правка`, `❓ Запитання`) та статусів (`OPEN`, `IN_REVIEW`, `RESOLVED`).
   - Кнопка `[ + Залишити правку / тікет ]`:
     - Модальне вікно з формою: вибір етапу, типу, введення повідомлення, вкладення посилання.
     - Викликає `POST /api/client/tickets`.
     - Миттєво додає створений тікет у список без перезавантаження сторінки.

### 4.4. Адмінський інтерфейс (Admin View)
- Список усіх проектів із бази (`GET /api/admin/projects`).
- Перегляд етапів будь-якого проекту з кнопками ручної зміни статусу (для тестування та оперативного керування).
- Список тікетів із можливістю в один клік перевести статус у `RESOLVED`.

### 4.5. Вимоги до надійності верстки (Layout Stability)
- Адаптивність під усі розміри екранів смартфонів (iPhone SE 375px — iPhone 15 Pro Max 430px — Android планшети).
- Відсутність горизонтального скролу (`overflow-x: hidden`).
- Обмеження контейнера `max-w-md mx-auto` для зручного перегляду на десктопі.
- Мінімальна висота клікабельних елементів — 44px (touch targets).
- Запобігання вильоту тексту довгих назв через `break-words` або `truncate`.

### 4.6. Збірка та інтеграція з FastAPI
1. Скрипт збірки `npm run build` у `frontend/` створює файли в `frontend/dist`.
2. У `main.py` додати монтування:
   ```python
   from fastapi.staticfiles import StaticFiles
   if os.path.exists("frontend/dist/assets"):
       app.mount("/assets", StaticFiles(directory="frontend/dist/assets"), name="assets")
   ```
3. У `src/api/routes/app_routes.py` роут `/app` віддає вміст `frontend/dist/index.html` із суворими anti-cache заголовками.

## 5. Критерії готовності (Definition of Done)
1. Фронтенд успішно збирається командою `npm run build` без помилок типізації чи збірки.
2. При переході за адресою тунелю `/app` відображається робочий додаток.
3. Усі ключові функції перевірено:
   - Проект завантажується з бекенду;
   - Модалка цифрового підпису відкривається, дозволяє розписатися та успішно апрувить етап №2;
   - Наступний етап розблоковується, прогрес перераховується;
   - Тікети створюються та відображаються у списку;
   - Перемикач на панель адміна працює;
   - Haptic Feedback викликається без помилок.
4. `python3 scripts/security_check.py` проходить із кодом 0 (жодних витоків секретів).
5. Надано звіт та єдину команду git commit.
